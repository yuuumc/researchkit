# v2.4.0 — Multi-step Research Agent + Session Memory + i18n

**Released**: 2026-07-24
**Type**: Minor
**Tag**: `v2.4.0`

---

## Summary

v2.4.0 upgrades ResearchKit from a "single paper → Knowledge Card" tool into a **multi-step research Agent service**. A free-text research goal is now turned into a grounded, cited answer via a `Planner → Step 1..N → Synthesizer` loop, with each `multi-agent` step reusing the v2.3.3 6-agent pipeline. Built for OKX AI Genesis Hackathon (ASP #6853).

---

## New Features

### 1. Multi-step Research Agent (`core/agent-loop/`)
- `runAgent(goal, maxSteps, locale)` — Planner LLM autonomously decides step kinds (`multi-agent` / `web` / `arxiv` / `memory-recall`), executes them in sequence, and Synthesizer LLM produces a grounded final answer with references.
- Each `multi-agent` step calls `coordinate()` — the v2.3.3 6-agent pipeline (Reader / Analyzer / Terminology / KnowledgeBuilder / Recommendation / Export) — so existing KC quality is preserved.
- Step kinds:
  - `multi-agent` — runs the full 6-agent pipeline on a sub-query
  - `web` — calls `web_search` tool (Wikipedia OpenSearch primary, DuckDuckGo fallback)
  - `arxiv` — calls `arxiv` tool for academic paper search
  - `memory-recall` — retrieves from session memory

### 2. Session Persistence + Resume
- `lib/persistence/session-store.ts` — file-based session store (`/tmp/researchkit-sessions/<id>.json` on Vercel, `.researchkit-data/sessions/` locally)
- Each session records: goal, steps (with status / duration / cost / output), materials (intermediate KCs), final answer
- `POST /api/agent/run` accepts `sessionId` — if the session exists, the Agent continues from where it left off
- `GET /api/agent/sessions` — list all sessions
- `GET /api/agent/sessions/[id]` — get session detail

### 3. Agent Run Tab in Main UI
- `AgentRunForm` + `AgentRunTimeline` embedded directly in the main UI's "Agent Run" tab (top toggle: `研究 / Agent Run`)
- Standalone `/playground/agent` route removed — no more experience split
- Settings (Provider / Preset / Output Language) now apply to Agent Run via `getServerUserPreferences()` cookie

### 4. Session History Drawer
- Right-side vertical floating button (purple gradient, `writing-mode: vertical-rl`)
- Drawer slides in from the right, mask does NOT cover the top bar (clickable)
- Lists past sessions with relative timestamps (`just now` / `5m ago` / `2h ago`)
- Click a session to view step-by-step detail (goal, steps, materials, final answer)

### 5. Full i18n for Agent Run UI
- New `agent-run.json` namespace (zh-CN + en-US)
- Covers: tab label, form labels, status badges, step kinds, references, final answer, session drawer
- `AgentRunTimeline.tsx` and `SessionHistoryDrawer.tsx` — zero hardcoded strings

## Bug Fixes

### Cost attribution (critical)
- **Problem**: `runAgent` didn't call `beginCollection()`, so Provider's `recordUsage()` had no ALS store → all costs showed as $0.0000.
- **Fix**: `beginCollection()` made idempotent — nested `coordinate()` calls reuse the outer collector instead of creating a new one. Each step's `costUsd` is now a delta (records after − records before), preventing cumulative double-counting.

### Tool parameter fixes
- **web_search**: switched primary source to Wikipedia OpenSearch API (DuckDuckGo anti-bot challenge was returning empty results); DuckDuckGo kept as fallback.
- **arxiv**: fixed `action: 'search'` missing + `maxResults` → `limit` / `max_results` parameter name mismatch.
- **Removed**: redundant `stage: 'done'` SSE event in `route.ts:152`.

### AgentRunTimeline crash
- **Problem**: `Cannot read properties of undefined (reading 'slice')` when Synthesizer LLM output omitted `materialId`.
- **Fix**: optional chaining `r.materialId?.slice(0, 18) || 'mat_?'` + `Array.isArray()` checks for `references` and `steps` fields.

### Settings FAB overlap
- **Problem**: Settings FAB (`top: 20px`) overlapped the `研究 / Agent Run` tab toggle.
- **Fix**: Settings FAB moved to `top: 80px`.
- **Drawer mask**: `inset: 0` → `top: 60px; left/right/bottom: 0` so the top bar stays visible and clickable.
- **Drawer z-index**: mask `9999`, detail modal `10001` (above Settings FAB `1000`).

## API

### New endpoints
| Method | Path | Description |
|---|---|---|
| `POST` | `/api/agent/run` | Run multi-step Agent (SSE streaming, `maxDuration=60`) |
| `GET` | `/api/agent/sessions` | List all sessions |
| `GET` | `/api/agent/sessions/[id]` | Get session detail |

### SSE contract (`/api/agent/run`)
Events: `ping` → `stage` → `agent_token` → `step_started` → `step_done` → `result` / `error`

## Architecture

```
Free-text Goal
   ↓
[Planner LLM] ── decides step kinds + queries
   ↓
[Step 1: multi-agent] → coordinate() → KC #1
[Step 2: web]          → web_search → snippets
[Step 3: arxiv]        → arxiv search → papers
   ↓
[Synthesizer LLM] ── grounds answer in materials + references
   ↓
Final Answer (cited)
```

## Known Risks

- **Vercel 60s timeout**: Complex multi-step goals may exceed 58s `Promise.race` guard. For demo, use `maxSteps=2-3` and simple goals.
- **Session store on Vercel**: `/tmp/` is ephemeral — sessions may be lost on cold starts. For persistent sessions, use a database backend (future work).
- **MCP tool `agent_run`**: Registered as an external callable entry; ensure `x-internal-key` is set if exposing publicly.
