# ResearchKit v2.4.0 Architecture

> From "Tool" to "Agent Service" — built for OKX.AI Genesis Hackathon

## 0. Why v2.4.0

v2.3.3 was registered as **ASP #6853** with endpoint `https://researchkit-mu.vercel.app/api/research/multi-agent-stream`,
free, 0 USDT. The endpoint accepts a single research paper and returns a Knowledge Card. This is
fundamentally a **tool** — a one-shot text-in / text-out transformation, not an Agent.

OKX.AI Genesis Hackathon's "Agentic Service Platform" category rewards entries that look like
**callable services with goals, memory, and tool use** — not text-transformation utilities. To move
ResearchKit into the "Agent service" bucket, v2.4.0 introduces:

| v2.3.3 (Tool) | v2.4.0 (Agent Service) |
|---|---|
| Input: a paper body | Input: a research **goal** (free-text) |
| Output: one KC for one paper | Output: a synthesized answer with `[1]/[2]/...` citations across multiple materials |
| Stateless across calls | **Sessions** — resume by `session_id`, reference prior materials |
| Single endpoint, single mode | SSE endpoint + MCP `agent_run` tool for ASP/MCP clients |
| Pipeline is internal | Pipeline is exposed as **composable tools** (Planner / Web / Arxiv / Multi-agent / Memory-recall) |

## 2. Component contracts

### 2.1 `runAgent(input: AgentLoopInput) → AgentLoopResult`

- **Input**: `{ goal, sessionId?, outputLocale?, maxSteps?, onStage?, onAgentToken?, signal? }`
- **Output**: `{ sessionId, finalAnswer, references[], steps[], totalCostUsd, totalUsage, totalDurationMs }`
- **Guarantees**:
  - `maxSteps` is clamped to `[1, 6]`, default 4
  - Each step failure is isolated (recorded as `failed` but loop continues)
  - `signal.aborted` is checked between steps; abort → returns partial result
  - Synthesizer always runs (with whatever step data we have)

### 2.2 Session store schema

```typescript
interface AgentSession {
  id: string                  // sess_<ts>_<rand>
  goal: string
  locale: string
  createdAt: number
  updatedAt: number
  status: 'running' | 'done' | 'failed' | 'cancelled'
  steps: SessionStep[]        // 0..N steps, each with kind/rationale/query/status/outputSummary
  materials: SessionMaterial[]  // dedup'd by (title+source), each with summary
  finalAnswer?: string        // populated when status='done'
  references?: Array<{ citeIndex, materialId, snippet }>
  totalCostUsd?: number
  totalUsage?: { promptTokens, completionTokens, totalTokens }
  error?: string              // populated when status='failed'
}
```

- Capacity: 50 sessions (FIFO)
- Storage: file-based JSON, atomic write via tmp+rename
- Vercel: `/tmp/researchkit-data/agent-sessions.json`
- Local: `.researchkit-data/agent-sessions.json`

### 2.3 `agent_run` MCP tool

- `name`: `agent_run`
- `input_schema`:
  ```json
  {
    "goal": { "type": "string", "description": "research goal (5..2000 chars)" },
    "session_id": { "type": "string" },
    "max_steps": { "type": "number", "default": 4 },
    "locale": { "type": "string", "enum": ["en", "zh", "zh-CN", "en-US"] }
  }
  ```
- `output`:
  ```json
  {
    "session_id": "sess_...",
    "final_answer": "...",
    "references": [{ "citeIndex": 1, "materialId": "mat_...", "title": "...", "source": "...", "snippet": "..." }],
    "steps": [...],
    "total_cost_usd": 0.012,
    "total_duration_ms": 12345
  }
  ```
- Synchronous — no SSE. For real-time progress, use `POST /api/agent/run`.

## 3. Failure modes & isolation

| Failure | Where | Behavior |
|---|---|---|
| Planner LLM returns invalid JSON | `planSteps` | Fallback to single-step web search |
| Step 1 fails (e.g. arxiv down) | `executeStep` | Mark step `failed`, continue to step 2 |
| All steps fail | `synthesize` | Synthesizer gets empty step results, returns minimal answer with error note |
| Synthesizer LLM returns invalid JSON | `synthesize` | Returns `Synthesis failed: invalid LLM JSON output.` |
| Vercel 60s hard kill | `route.ts` | 58s Promise.race → send `error` event with friendly message |
| Client disconnects mid-run | `request.signal.aborted` | Checked between steps; loop returns partial result |
| Same material already in session | `addMaterial` | Dedupe by (title+source), reuse existing material_id |
| `coordinate()` 58s timeout | `coordinate()` (v2.3.3) | Returns partial KC; orchestrator treats as step `done` with whatever KC came back |

## 4. Cost & performance

- **Tokens per agent run** (rough estimate, depends on goal length & step count):
  - Planner: ~500 prompt + ~200 completion
  - Each step: depends on kind
    - `web_search`: ~0 (tool is no-LLM)
    - `arxiv`: ~0 (tool is no-LLM)
    - `multi-agent`: ~3000-8000 prompt + ~2000-4000 completion (v2.3.3 6-agent pipeline)
    - `memory-recall`: ~0
  - Synthesizer: ~2000-4000 prompt + ~1000-2000 completion
- **Total typical**: 5000-15000 prompt + 3000-6000 completion
- **Latency typical**:
  - Goal with 1 web + 1 multi-agent: 30-60s
  - Goal with 2 multi-agent: 60-120s → **may exceed Vercel 60s hard limit on 2+ multi-agent steps**
  - Vercel hard limit = 60s; we Promise.race at 58s; recommend Vercel Pro or async job queue for long runs
- **Cost dashboard**: `step.costUsd` and `session.totalCostUsd` are populated; UI can read from `session.steps`

## 6. Deployment

- **No new env vars needed** — uses existing `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `LLM_MODEL`
- **Storage** — Vercel `/tmp/` is ephemeral per-instance; sessions will be lost on cold start. For hackathon demo this is acceptable. For production, swap `lib/persistence/session-store.ts` to use Postgres / Upstash Redis.
- **Vercel function timeout** — `/api/agent/run` is set to `maxDuration = 300` but Vercel free tier hard-kills at 60s. Long runs need Vercel Pro or a job queue. We surface 58s timeout as a friendly error event.
- **Concurrency** — no locking. If the same `session_id` is used concurrently, last write wins. Acceptable for demo.

## 7. Smoke test

```bash
# Health
curl -s https://researchkit-mu.vercel.app/api/agent/run | jq

# Tool list (should include agent_run)
curl -s https://researchkit-mu.vercel.app/api/tools/list | jq '.tools[].name'

# Synchronous agent run (small goal, 1-2 steps expected)
curl -s -X POST https://researchkit-mu.vercel.app/api/tools/call \
  -H 'Content-Type: application/json' \
  -d '{"tool":"agent_run","input":{"goal":"Compare AlphaFold 2 and AlphaFold 3","max_steps":2}}' \
  | jq '.result | {session_id, final_answer: (.final_answer[0:200] + "..."), references: (.references | length), step_count: (.steps | length)}'

# SSE agent run (full pipeline, progress stream)
curl -N -X POST https://researchkit-mu.vercel.app/api/agent/run \
  -H 'Content-Type: application/json' \
  -d '{"goal":"What are the latest advances in diffusion models for protein design?","max_steps":3}'

# Session list
curl -s https://researchkit-mu.vercel.app/api/agent/sessions?limit=5 | jq

# Single session
SID=$(curl -s -X POST https://researchkit-mu.vercel.app/api/agent/sessions \
  -H 'Content-Type: application/json' -d '{"goal":"Test session creation"}' | jq -r '.session.id')
curl -s "https://researchkit-mu.vercel.app/api/agent/sessions/$SID" | jq
```
